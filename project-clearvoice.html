Software Development / Project 01

ClearVoice v0.2.5

청각장애가 있는 지인과의 소통에서 시작한 Windows 실시간 음성 자막 프로젝트.

개발 계기문제와 해결실제 화면현재 상태

01 / WHY CLEARVOICE

함께 대화하기 위해 시작했습니다.

청각장애가 있는 지인과 소통하기 위해 ClearVoice를 만들기 시작했습니다.

Discord와 같은 음성 채팅 환경에서 상대방의 말을 자막으로 확인할 수 있도록 돕는 것이 목표였습니다. Windows에서 재생되는 소리를 받아 글자로 바꾸고, 게임이나 다른 프로그램 위에서도 읽을 수 있는 오버레이로 연결했습니다.

음성 인식 기능을 붙이는 데서 끝나지 않았습니다. 자막이 늦게 도착하는 문제, 다른 PC에서 실행되지 않는 문제, 화면을 조작하기 어려운 문제를 해결하며 실제 사용할 수 있는 앱으로 다듬었습니다.

프로젝트
Windows 음성 자막 접근성 앱
담당 범위
구조·UI/UX 설계, 오디오·STT 통합, 상태 관리, 테스트·패키징
주요 기술
Electron · React · TypeScript · Python · Faster-Whisper · CUDA

02 / ENGINEERING JOURNEY

실제로 사용할 수 있게 만들기까지

개발 당시 작성된 트러블슈팅 기록에서 대표 사례 네 가지를 정리했습니다. 아래 결과는 당시 구현 기록을 기준으로 합니다.

01

실시간 자막의 지연과 자원 부담

Whisper.cpp에서 Faster-Whisper로

문제
Whisper.cpp Medium 계열을 게임과 함께 실행할 때 자막 처리 지연과 GPU 부담이 문제가 되었습니다.
해결
양자화 모델 검토, 무음 구간 건너뛰기, 큐 최적화와 중복 작업 제거를 거친 뒤 Faster-Whisper Medium을 도입했습니다. 기존 자막 처리 흐름은 유지하고 추론 엔진을 교체했습니다.
결과
개발 기록에서는 실사용 반응성이 개선되어 CUDA float16 기반 Faster-only 배포 구조로 전환했다고 정리합니다. 성능 개선율은 별도 수치로 제시하지 않습니다.
02

개발 PC 밖에서 실행되지 않는 설치본

런타임부터 패키징까지 독립적으로

문제
복사한 Python 가상환경이 개발 PC의 경로를 참조했고, 모델·런타임을 포함한 설치 파일이 2GB를 넘으면서 기존 NSIS 패키징도 실패했습니다.
해결
Windows Embedded Python과 필요한 패키지를 포함하고, 앱 내부에서 Python·모델·worker 경로를 찾도록 구성했습니다. 중복 엔진 구성을 줄이고 7-Zip SFX 기반 단일 EXE로 패키징 방식을 변경했습니다.
결과
사용자가 Python과 모델을 별도로 설치하지 않도록 오프라인 설치 구조를 마련했습니다. 이는 당시 구현 결과이며, 현재 모든 PC에서의 호환성을 보장하는 의미는 아닙니다.
03

움직일 수 없는 오버레이, 어긋나는 편집 상태

보기와 편집의 전환을 하나의 흐름으로

문제
클릭 통과 상태가 편집 모드에도 남아 창을 이동할 수 없었고, 편집을 마친 뒤에도 일부 화면에는 편집 중 상태가 남았습니다.
해결
편집 진입·종료 처리를 분리해 입력 허용, 이동·크기 조절, 위치 저장, 클릭 통과 복원을 함께 처리했습니다. Electron Main의 실제 창 상태를 기준으로 메인 화면과 오버레이에 변경을 전달했습니다.
결과
개발 기록상 위치 수정 → 완료 → 다시 위치 수정의 반복 흐름을 안정화했습니다. 화면마다 따로 관리하던 상태를 실제 창 상태에 맞춰 동기화한 사례입니다.
04

끝나지 않는 연결 중 상태

성공뿐 아니라 취소와 복구까지

문제
Discord Bridge가 응답하지 않으면 연결 중 상태에서 빠져나오기 어려웠습니다. 취소 후 늦게 도착한 응답이 현재 상태를 바꿀 가능성도 있었습니다.
해결
연결 시도마다 Attempt ID, AbortController, 20초 제한시간을 적용했습니다. 취소할 때 요청·WebSocket·타이머를 정리하고, 지난 시도의 응답은 현재 상태에 반영하지 않도록 했습니다.
결과
성공·취소·시간 초과·오류 각각의 복귀 경로와 재연결 흐름을 마련했습니다. 과거 수동 테스트 기록과 현재 Discord 봇 시연 가능 여부는 구분합니다.

범위를 정하는 것도 개발의 일부였습니다.

GPU 감지와 실행 검증을 분리했습니다. 장치가 보이는 것만으로 동작을 판단하지 않고, 실제 추론 테스트와 런타임 진단을 추가했습니다. GPU 세대 전체의 호환성을 일괄 보장하지 않습니다.

독점 전체화면 지원은 제한으로 남겼습니다. Electron 오버레이의 한계를 고려해 창 모드·테두리 없는 전체화면을 중심으로 범위를 정했습니다. Xbox Game Bar 방식은 별도 배포와 구현 복잡도를 고려해 보류했습니다.

메뉴는 사용자 행동을 기준으로 정리했습니다. 개발자 중심 메뉴를 홈·오버레이·설정·도움말로 재구성하고, 연결 → 시작 → 중지 흐름과 실제 상태가 드러나도록 개선했습니다.

03 / PRODUCT WALKTHROUGH

실제 화면으로 살펴보기

제공된 v0.2.5-external-test 스크린샷입니다. UI와 설정 흐름을 보여주며, 현재 환경에서 연결·음성 인식을 다시 검증한 자료는 아닙니다.

SETUP / FIRST RUN

처음 실행하는 순간

GPU 선택 후 출력 장치를 검색하고 선택하는 초기 설정 흐름입니다. 이미지를 누르면 크게 볼 수 있습니다.

PAIRING / CONNECTION

페어 코드로 연결하기

Discord Bridge 연결을 위한 코드 입력 화면입니다. 연결 완료 장면은 포함되어 있지 않습니다.

OVERLAY / SETTINGS

자막과 앱 환경 설정

오버레이의 모양과 표시 방식, 앱 테마와 자막 언어를 설정하는 화면입니다.

04 / CURRENT STATUS

구현 기록과 현재 시연 범위

개발 당시에는 Faster-only 설치 패키징과 외부 테스트를 진행했습니다. 현재는 최종 설치본과 스크린샷을 보유하고 있으며, Discord 봇과 최신 소스에는 접근할 수 없습니다. 당시의 구현 결과를 현재 운영 중인 서비스로 소개하지 않습니다.
